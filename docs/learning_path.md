# 从数据到提交：本项目的训练主线

## 1. 数据集角色

- `train`：模型看得到图像和答案，用于反向传播更新参数。
- `val`：模型只用于评估，不参与参数更新；用来选择模型、阈值和超参数。
- `test`：没有公开答案，只用于生成 Kaggle 提交。

最重要的纪律是：同一轮实验只改变一个主要因素，并保持验证划分不变。否则分数变化无法归因。

## 2. 一次训练发生了什么

1. DataLoader 读取一批图像与边界框。
2. 模型前向计算，输出类别概率和候选框。
3. 损失函数衡量预测与真值之间的差距。
4. 反向传播计算每个参数对损失的梯度。
5. 优化器更新参数。
6. 一个 epoch 结束后，在验证集计算 mAP@[0.5:0.95]。
7. 保存验证指标最好的权重 `best.pt`，而不是盲目使用最后一个 epoch。

## 3. 为什么先做伪 RGB

标准预训练检测器是在三通道自然图像上训练的。先从 16 个波段中选 3 个生成伪 RGB，可以快速验证：

- 数据读取和框坐标是否正确；
- 模型能否正常训练；
- 本地验证与 Kaggle 提交流程是否打通；
- 哪些类别主要依靠形状即可识别。

它是工程基线，不是最终方案。若 16 通道模型没有超过这个基线，通常说明光谱融合或归一化还没有发挥作用。

## 4. 实验记录

每次正式实验在 `experiments/experiments.csv` 中记录：

- 代码版本；
- 波段选择；
- 模型和预训练权重；
- 图像尺寸、batch size、epoch；
- 本地 mAP50-95、mAP50；
- Kaggle 分数；
- 结论和下一步。

## 5. 当前阶段门槛

在进入 16 通道模型前，伪 RGB 基线必须满足：

- 数据审计无致命错误；
- 训练、验证和测试图像数量正确；
- 训练 loss 能下降；
- 验证集可生成 mAP；
- 提交 CSV 字段、类别编号、坐标范围和图片覆盖完整；
- Kaggle 至少成功接受一次提交。
